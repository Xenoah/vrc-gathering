# VRC Friends Observer v0.6.1

自分のVRChatアカウントに公開されているフレンドの接続状態・ワールド・インスタンスを定期取得し、PC内へ記録するChrome拡張です。**ローカル利用時はコンパイル・Node.js・Python・外部サーバーは不要**です。Googleスプレッドシート同期を使う場合は、同梱手順でGASを公開します。

Windowsログオン後、対象のChromeプロファイルが動いている間に収集します。VRChatのゲーム本体や公式サイトのタブを開き続ける必要はありません。Chromeのバックグラウンド実行を有効にすれば、通常のウィンドウを閉じた後も動作できます。Chromeの完全終了、Windowsのサインアウト／スリープ中は収集できません。

## 導入

1. ZIPを `C:\Tools\VRCFriendsObserver` などの固定フォルダーへ展開します。導入後もこのフォルダーを残してください。
2. Chromeで `chrome://extensions` を開き、右上の「デベロッパーモード」を有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」から **`extension` フォルダー**を選びます。`manifest.json` が直接入っているフォルダーです。
4. 同じChromeプロファイルで https://vrchat.com/home にログインし、2段階認証も完了します。
5. 拡張のダッシュボードで「収集設定」を開き、自分の連絡先メールアドレスまたはHTTPSプロフィールURLを保存します。例：自分のGitHubプロフィール。VRChat APIが求めるアプリ識別用です。
6. 「収集を開始」を押します。最初の観測結果が表示されれば導入完了です。

初回は停止状態です。拡張のアイコンからダッシュボードを何度でも開けます。パスワード・2FAコード・認証Cookie・認証トークンを拡張へ入力する項目はありません。

## Windows起動時の収集

Chromeの「設定 → システム → Google Chromeを閉じた際にバックグラウンドアプリの処理を続行する」を有効にします。本拡張はChromeの `background` 権限を宣言しています。ただし組織ポリシー、OSのスタートアップ設定、Chromeプロファイルの使用状況により自動起動が制限される場合があります。

必要なら、同梱の `windows/Install-Startup.ps1` をPowerShellから実行します。現在のWindowsユーザーのスタートアップフォルダーにChromeのショートカットを1つ追加します。管理者権限は不要です。

```powershell
powershell.exe -NoProfile -File ".\windows\Install-Startup.ps1"
```

VRChatを「Profile 1」などで使っている場合：

```powershell
powershell.exe -NoProfile -File ".\windows\Install-Startup.ps1" -ProfileDirectory "Profile 1"
```

正しいプロファイル名は `chrome://version` の「プロフィール パス」の末尾で確認します。通常の表示名とは異なります。既存の同名ショートカットは上書きしません。Chrome、拡張、バックグラウンド実行の設定を済ませてから利用してください。

PowerShellの実行ポリシーでスクリプトを使えない場合は、`Win + R` → `shell:startup` にChromeのショートカットを手動で作成し、リンク先の末尾に `--profile-directory="Default" --no-startup-window` を付けても設定できます。PCの管理ポリシーを変更する必要はありません。

解除：

```powershell
powershell.exe -NoProfile -File ".\windows\Remove-Startup.ps1"
```

解除スクリプトは上記ショートカットだけを削除します。Chrome自体、レジストリ、サービス、タスクスケジューラー、VRChatアカウント設定は変更しません。Windowsログオン前のサービス動作には対応しません。

## 記録内容と画面

| 情報 | 扱い |
| --- | --- |
| フレンドID・表示名 | 自分のフレンド名簿から取得 |
| 接続状態 | ゲーム内／Web・アプリ／オフライン／不明 |
| ステータス・メッセージ | APIが返す内容。名前・状態文の取得日時も別に保持 |
| プラットフォーム | APIのplatform、なければlast_platform。後者は直近の利用プラットフォームであり現在の端末とは限らない |
| ワールドID・名称 | 自分に公開されたIDのみを使用。名称・作者名・定員は24時間キャッシュ |
| インスタンスID・種類・地域 | 公開されたlocationを解析。種類はIDのタグに基づく表示で、参加権限の保証ではない |
| private / traveling / 不明 | そのまま区別して保存。過去のワールドを現在地に流用しない |
| 変更履歴 | 状態・場所・表示名などが変わった観測だけを保存 |
| フレンド名簿からの消失 | 完全な名簿で確認できた場合のみ記録。ブロックされたとは判定しない |

ワールドの定員はインスタンスの現在人数ではありません。同席者全員の取得、フレンド外のプロフィール巡回、非公開の居場所の推測は実装していません。アバターの3Dアセット、実名、外部SNSのID、メールアドレス、自己紹介文などは記録対象に含めません。

- 検索：表示名、ユーザーID、ワールド名、インスタンスID、ステータスメッセージ。
- フィルター：接続状態、所在非公開、古い観測、名簿から外れたフレンド。
- 行をクリック：詳細と直近の変更を表示。公式サイトのプロフィール／ワールドも開けます。
- アカウント選択：別アカウントの記録は分離します。収集するのは現在そのChromeでログインしているアカウントです。
- デモ：「使い方」のリンクで架空データを表示します。デモはAPI接続・収集・保存を行いません。

## Intelligence UI：概要・分析・探索

画面入口は「概要」（Command Center）で、最新の観測状態・最近の変化・公開ワールドを一覧できます。「分析・タイムライン」は横軸を時刻 t（JST）、縦軸をユーザーとして、記録された状態の時間的分布を表示します。「探索・遷移図」には従来のワールド遷移ネットワークをそのまま残しています。フレンド一覧・ランキング・変更履歴・設定も従来どおり利用できます。

### ユーザー活動タイムライン

- 期間：直近6時間、24時間、7日間、30日間。ユーザー名／ワールド名の検索と表示対象フィルターがあります。
- 公開ワールド、所在非公開、Web／アプリ、オフライン、状態不明を色分けします。公開ワールドの名称はバーにマウスを重ねると確認できます。バー／名前からフレンドの詳細を開けます。
- 縦線は実際の観測点です。斜線入りバーは観測点間から補間した**推定区間**です。観測点の前後も含め、正確な入退室時刻や連続在室を保証するものではありません。
- 最後の観測より後を自動でオンラインとして延長しません。古い観測・停止・スリープ・通信失敗・取得ページの欠落により、実際の行動が未観測になり得ます。
- 「時刻ごとの変化観測数」は変更イベントの件数であり、オンライン人数、利用時間、活動率そのものではありません。

### フレンド一覧の継続時間

一覧には「観測上の継続」列が追加されます。接続／オフライン等の状態について、最新の観測時刻と状態が継続していると扱われた起点との差を表示します。公開ワールド滞在中は「同一ワールド」継続も併記します。フレンド詳細では状態の継続が確認できます。

状態・同一ワールド・同一インスタンスの起点は別々に管理し、表示名やステータスメッセージの編集では「接続継続」をリセットしません。起点は既存の同期レコードの namespaced extensions に保存され、Googleスプレッドシート同期にも引き継がれます。起点に対応する観測時刻も保存し、旧版端末から届いた新しい状態に古い起点を誤用しないよう照合します。旧版の記録には独立した起点がないため、従来の「同じ状態の最初の観測」から保守的に算出します。

「継続時間」は推定値です。観測間で離脱・再接続が起きても検知できなければ同じ区間に見えます。実際にいつ接続／入室したかは確定できません。

## ユーザー情報からX（Twitter）を開く

フレンド一覧などでユーザーを選ぶと、詳細の上部に「X（Twitter）」が表示されます。公開プロフィールのリンク欄・自己紹介にX／TwitterのプロフィールURLがあれば、クリックして別タブで開けます。最大5件を表示します。名前や単独の `@ユーザー名` からアカウントを推測しません。

初回・24時間経過後に、VRChatの公開プロフィールを取得します。取得には同じChromeでのVRChatログインと、収集設定の連絡先が必要です。「Xリンクを更新」で再確認できますが、直近1分以内はキャッシュを使います。収集中は完了を待ち、待ち時間が長い場合はボタンで再試行できます。リンク未掲載・取得失敗は区別して表示します。

保存するのはアカウント／ユーザーID、確認日時、正規化したXプロフィールURLだけです。自己紹介の本文や生の応答は保存しません。`chrome.storage.local` に最大500ユーザー分をアカウント別にキャッシュします。このキャッシュはGAS同期・履歴JSON・設定バックアップの対象外で、「この端末の記録を削除」で消去します。GAS更新は不要です。

プロフィール取得は `/profile/{userId}` と前後のアカウント確認に限定し、通常の収集と同じ待機時間・アクセス制限を守ります。プロフィールを取得しても、以前の居場所の観測日時は更新しません。X自体への通信はリンクをクリックしたときだけです。

## 分析ラボ：31種類の分析

「分析ラボ」で保存済みデータを横断的に集計できます。初期表示は7日間の概要・期間比較です。カテゴリを選ぶか、分析ツール名を検索して切り替えます。

| カテゴリ | 分析ツール |
| --- | --- |
| 概要・比較（3） | 前期間との比較、日別の変化・観測カレンダー、ワールドの注目度の変化 |
| 時間帯（3） | 曜日×時間帯ヒートマップ、時間帯別の傾向、曜日別の傾向 |
| ワールド（2） | ワールド別の観測・流入・流出、現在の注目ワールド |
| 移動（3） | よく観測された移動経路、往復パターン、ユーザー別の探索傾向 |
| 自分の行動（4） | 再訪・滞在傾向、滞在区間の分布、平均・中央値・90パーセンタイル、同席を確認できた時間の割合 |
| つながり（8） | 同席相手ランキング、つながりの変化、継続／今期のみ／前期のみの同席、保存範囲で初めて同席した相手、人と重なるワールド、共通ワールドネットワーク、共通ワールドでつながるグループ、2ユーザー比較 |
| 記録の内訳・品質（8） | 状態の内訳、プラットフォーム分布、公開範囲の内訳、リージョン分布、変更項目、最新記録の鮮度、収集履歴の充足状況、収集記録の長い空白 |

### 絞り込み・操作・出力

- 期間は24時間・7日・30日・90日・365日、またはJSTの日付指定。終了日はその日を含み、未来の時刻は現在までに制限します。最大366日です。保存日数より前の記録は復元しません。
- フレンドとワールドで絞り込めます。フレンド指定はフレンド・同席の集計に適用し、自分の履歴は期間・ワールドで絞ります。巡回の充足状況や空白はアカウント全体です。
- 日別グラフは変更件数・ユーザー数・ワールド変更・自分の時間・同席人数を選べます。棒を選ぶとその日に絞り込めます。ヒートマップのセルを選ぶと件数を確認できます。
- 表の見出しで昇順／降順に並べ替え、50件ずつ追加表示できます。共通ワールドネットワーク・グループとその表・出力は、観測ワールド数順に20・40・80人が対象です。最小共通ワールド数も指定できます。その他の集計・出力は全件が対象です。
- 図はドラッグ・スクロール・ピンチ／Ctrl＋ホイールに対応。線を選ぶと、2ユーザーの共通ワールドと類似度が更新されます。ドロップダウンでも比較相手を選べます。
- 各分析のCSV、全分析の集計CSV、分析JSONを書き出せます。JSONには期間・アカウント・絞り込み条件・指標の定義を含み、時間の数値はミリ秒です。CSVは画面と同じ時間表記です。

### 数値の読み方

「観測点」は変更履歴の前後状態と最新状態を、ユーザーID・日時で重複排除した件数です。全巡回の全員分のスナップショットではなく、状態変更が多いユーザーの記録が多くなります。観測点数やヒートマップを在室人数・利用時間・在室率として扱わないでください。

前期は選択した期間の直前にある同じ長さの期間です。前期の記録がない場合も0になり、比較元が0なら増減率は算出しません。保存期間・取得回数の差でも増減します。「初めて」は保存範囲で最初という意味で、実際の初対面ではありません。

自分の時間と同席時間は最終確認までの推定です。1回だけの観測は時間未確認として長さの統計から除外します。重なる端末の観測を二重加算せず、区間をJSTの日付・時刻の境界で分割します。「同席未確認の時間」は一人だった時間とは限りません。ワールド別の同席延べ時間は相手ごとの合計です。

共通ワールド図の線・グループは訪問先の重なりで、同時刻の同席、VRChat上のフレンド関係、親密さを表しません。2ユーザーの類似度は共通ワールド数を両者のワールドの和集合で割ったJaccard係数です。共通の観測時間帯も、同じ日・時刻にいたことを意味しません。

追加のAPI取得・外部への分析送信はありません。既存の同期で取得した記録にも使え、v0.5.0用GAS・DB形式・設定をそのまま利用できます。分析のためのGAS再デプロイは不要です。

## 自分の訪問履歴・ユーザーとのつながり

「自分・つながり」タブで、自分がいたワールドと、そのとき場所が重なったフレンドを確認できます。通常の収集を開始すると記録されます。自分の現在地は既存の `/auth/user` 応答から必要な項目だけを選別し、ホームワールドの設定値からは推測しません。Web／アプリのみ・オフライン・所在非公開・情報欠落は、それぞれの状態として保存します。

- **同じインスタンス**：ワールドIDと空でないインスタンスIDが一致した観測。既定の表示対象です。
- **同じワールド・インスタンス一致未確認**：ワールドIDは一致するものの、インスタンスが違う／一方のIDが得られない観測。同席とは区別します。
- **図と表**：自分を中心に、重なったユーザーを表示。回数、観測上の重なり時間、共通ワールド数、最後の観測、名前で並べ替えられます。期間・ワールド・ユーザーで絞り込めます。
- **根拠の確認**：名前や図の点・線を選ぶと、区間・ワールド・双方のインスタンスIDを表示します。図はドラッグ・スクロール・拡大縮小に対応します。
- **自分の履歴**：訪問区間、最後の観測、インスタンスを確認できます。全履歴JSONにも `visits` と `encounters` が含まれます。

フレンド取得の前後で自分の場所が一致する場合だけ、その巡回内の新しいフレンド観測を照合します。途中で移動した巡回、所在非公開、未取得のページから同席を推測しません。同じ状態が近接する巡回で続いた区間だけを伸ばし、停止・失敗などで長い空白があれば区切ります。1回だけの観測は「時間未確認」です。複数端末の重複した区間は時間の集計で二重加算しません。正確な連続在室や会話・親密さは断定できません。

新機能を使って収集した時点以降の記録が対象です。過去のフレンド履歴から、自分の居場所や同席をさかのぼって推測することはありません。取得できるのは自分から見えるフレンド情報のみで、同じ部屋の全参加者一覧は収集しません。

保存済みの設定・従来の記録・画像キャッシュを残して、IndexedDBをバージョン3へ移行します。GAS同期では専用の **VRCVisits** と **VRCEncounters** を追加します。GASの2ファイルを差し替え、同じ設定で `setup` を実行して再デプロイしてください。更新前のGASでは従来の記録だけ同期し、新しい履歴は端末内に保持します。GAS更新後には未送信の履歴を同期します。旧拡張には対応する従来の記録だけを返します。

## ワールドランキングと遷移図

「ワールドランキング」は、選択中アカウントのフレンドのうち、新しい観測でゲーム内・ワールド公開になっている人数を集計します。同じユーザーの重複は数えず、同じワールドの複数インスタンスをまとめます。同人数は同順位です。古い観測・オフライン・所在非公開・名簿から外れたユーザーは除外します。ワールド全体の接続人数や人気を示すものではありません。

「ワールド遷移」は、選択したアカウントで記録した全ユーザーの移動を重ねたネットワーク図です。ワールドを点、観測順の移動を矢印にし、線の太さで観測回数を表します。ドラッグでパン、ホイールでスクロール、Ctrl＋ホイールまたはピンチでズームできます。「全体を表示」、＋／−、100%ボタンも利用でき、キーボードでは矢印・＋／−・Homeに対応します。

ユーザー・期間・ワールド名やユーザー名で絞り込み、配置順を移動回数・現在人数・観測ユーザー数・最新観測・名前から選べます。点／線をクリックするか、下の詳細選択欄を使うとユーザー・前後の観測時刻・インスタンスを確認できます。ネットワークは保存済み履歴全体を使い、200件に制限しません。1人を選んだ場合は、折りたたみ欄で最新200地点の時系列も確認できます。

非公開・オフライン・移動中等は独立した状態の点です。同じワールド内のインスタンス変更は自分へ戻る線で示します。矢印は観測順で、正確な移動時刻や途中の経路を保証しません。点の配置・距離は地理や時間を表しません。

一覧の並べ替えは接続状態、名前／逆順、ワールド名、新しい／古い観測、同じ状態の観測開始、プラットフォーム。ランキングは人数、インスタンス数、観測時刻、名前を選べます。ランキングの順位番号は並べ替えても滞在人数に基づく順位です。

### 画像キャッシュ

「収集設定 → ユーザー・ワールドの画像キャッシュ」で有効にし、追加接続権限を許可します。収集で得たユーザーアイコン（なければプロフィール／アバターのサムネイル）とワールド画像を128pxに縮小して端末に保存し、一覧・ランキング・ネットワークで再利用します。VRChatが公開している画像参照だけを扱い、未取得や失敗時は頭文字を表示します。

収集が動作中に最大12件ずつ取得します。既存の観測だけに画像URLはないため、有効化後の通常収集で順次補完します。上限は全アカウント合計32MiB・1,000件、7日で再取得、30日未観測の画像を整理します。画像設定をオフにすると追加取得を止め、既存キャッシュは閲覧に使えます。「画像キャッシュを削除」で画像だけを消せます。

画像Blobと取得元URLは専用のローカルストアに分離し、GAS・CSV・JSONには含めません。別端末に同期されるのは観測記録のみで、閲覧専用端末では画像未取得の場合があります。

## Googleスプレッドシートとの同期

拡張の「収集設定」または「使い方」から「GASセットアップ手順を見る」を開きます。6ステップのガイドに沿ってスプレッドシートとGASを新規作成し、「収集設定 → Googleスプレッドシート同期」にURLと同期キーを保存します。ガイド内から `Code.gs` と `Protocol.gs` をコピー・保存できます。詳しい補足は [gas/README.md](gas/README.md) にもあります。同期は任意です。収集後・画面表示時・約5分ごとに差分を送受信し、「今すぐ同期」でも更新できます。

全アカウントの観測データを同期します。VRChatの認証情報とAPI連絡先は同期しません。通信エラー時はローカルの記録を表示し、待機後に再試行します。クラウドと端末の保存期間は独立しています。端末内の記録削除はクラウドには伝わらず、同期を再開するとクラウドに残った記録が戻ります。

## 取得方法

既定は3分ごと、前後10%のランダム幅です。実際の巡回間隔は処理にかかった時間を含むため、厳密な3分周期ではありません。

1. ログイン中の自分のIDとフレンドID名簿を確認します。
2. オンライン／Web利用中のフレンドを100件ずつ、最大20ページ取得します。
3. オフライン名簿の名前などを初回・既定60分ごとに更新します。1巡回の上限は5ページです。オフラインへの状態変化は通常巡回の自分の名簿でも確認します。
4. 公開ワールド名を1巡回最大5件補完します。
5. 自分のアカウントIDをもう一度確認し、変わっていなければまとめて保存します。

上限を超えた名簿は次回に続きから取得します。ワールド名の未取得分も次回以降に補完します。APIのページングは厳密な時点固定スナップショットではないので、取得中の状態変化で重複や取りこぼしが起こり得ます。重複IDは観測時刻が新しい方を採用し、一覧に見当たらないだけでオフラインやフレンド解除とは判定しません。

大量データでは全件の更新に複数巡回かかります。表示は最終観測時刻を伴います。通常更新間隔の約2.2倍（最低2分）を過ぎたものは「古い観測」と表示し、トップの現在状況の件数から除外します。

## 観測の限界

これは定期観測です。移動が起きた正確な瞬間、取得と取得の間の短時間の滞在、スリープ中の活動は復元できません。変更履歴の `previousObservedAt` と `observedAt` は前回・今回の観測時刻であり、正確な入退室時刻ではありません。取得が失敗した巡回は保存せず、次の取得まで空白になります。

所在が非公開になった後も、公開されていた時点の履歴は保存期間内に残ります。現在欄には過去の場所を出しません。記録やエクスポートの扱いは、フレンドの意図とVRChatのルールを尊重してください。

Chromeの拡張サービスワーカーは休止することがあります。定期処理には `chrome.alarms` を使い、アラーム消失時は再作成、処理中断時は次の巡回で再開します。PCを起こす機能や取り逃した巡回の一括リプレイはありません。

## エラーと認証

- `401` / 2FA要求：自動収集を停止。同じプロファイルの公式サイトでログインを完了し、「収集を開始」で再開します。
- `403` / API転送 / 応答形式変更：自動収集を停止します。サイトと仕様を確認してください。
- `429`：Retry-Afterと指数バックオフの長い方を守ります。保存データ削除や停止／再開では待機を解除しません。
- 通信障害・サーバーエラー：指数バックオフ、最大通常6時間。Retry-Afterが長い場合はそれ以上待ちます。
- 手動更新・停止後の再開も、巡回開始から最低60秒、個々の要求は最低2.2秒を空けます。
- 取得途中のアカウント切替：その巡回を破棄して停止します。

Chromeのサイトアクセスは「vrchat.comで常に許可」にしてください。「拡張をクリックしたときのみ」ではバックグラウンド収集できません。Cookie制限や組織ポリシーにより、サイトへログイン済みでも拡張から認証できない場合があります。Cookieの手動コピーや別ドメインへの転送では回避しません。

## データ保存・出力

記録はChromeプロファイル内の拡張専用IndexedDB、設定は `chrome.storage.local` です。同期を有効にすると、指定のGAS経由でGoogleスプレッドシートにも記録を保存・取り込みます。Chrome Syncは使いません。ブラウザ自身が既存セッションをAPI通信に付けますが、拡張はCookie APIを使わず、Cookie・認証トークンを読み出したり保存したりしません。自分のAPI応答は必要な項目のみ選別して扱い、生レスポンスをログ／ファイルに残しません。

既定保存期間は30日、画面の選択肢は7〜365日です。設定ファイルでは1〜365日を指定できます。履歴と最後に更新されてから期間を過ぎたデータを巡回時・起動時・稼働中の保守処理で削除します。PC停止中は削除処理も動かず、次の起動後に処理します。設定短縮時にも削除します。

- **一覧CSV**：選択アカウントの保存済みフレンド全件。画面フィルターや1,000件の表示上限に左右されません。
- **履歴CSV**：選択アカウントの変更履歴全件。画面に出る直近200件に限りません。
- **全履歴JSON**：一覧、変更履歴、ワールドキャッシュ、巡回記録、自分の訪問履歴、同席の観測区間。アカウントごとに書き出します。

CSVはUTF-8 BOM付き、数式として解釈され得るセルは先頭にアポストロフィを加えます。画面の時刻はJST、CSV／JSONの日時表現はISO 8601 UTC、内部タイムスタンプはUnixミリ秒です。全履歴JSONの手動再インポートには対応していません。GAS経由の同期では他端末の記録を取り込めます。記録はアプリ独自暗号化をしていません。

Chrome拡張の削除・プロファイル削除でデータが消えるため、必要な履歴は削除前に書き出してください。

## 設定の書き出し・読み込み

「収集設定」の上部にある「設定のバックアップ」を使います。

1. **設定を書き出し**：保存済みの連絡先、更新間隔、保存日数、名簿再取得間隔、GASのURL・同期有効状態、画像キャッシュの有効状態をJSONで保存します。未保存の入力は含みません。
2. 別端末へ同期キーも移す場合は **同期キーも含める** をチェックして書き出します。キーは暗号化されずに保存されるため、ファイルをご自身で管理してください。通常の書き出しにはキーを含めません。
3. **設定を読み込み** でJSONを選び、内容を確認して **この設定を読み込んで保存** を押します。現在の設定と未保存の入力を置き換えます。キャンセルや不正なファイル、接続権限の拒否では設定を変更しません。
4. 収集は停止した状態になります。必要なら **収集を開始** を押してください。Google同期はキーが揃っていればファイルの有効状態を復元し、必要な接続権限を確認します。

キーなしのファイルは、同じGASのURLに限って端末内の保存済みキーを維持します。別URLや新しい端末では同期を無効にして読み込みます。GASのSYNC_TOKENを入力して同期を有効にし、保存してください。

記録・画像・アカウント情報・実行中の状態・GAS側のスクリプトプロパティは対象外です。読み込み自体は既存の記録や画像を削除しません。保存日数を短縮した場合は、その後の自動整理で期限外の記録が削除されます。APIの待機期限は引き継ぎ、同じGASへのサーバー指定の待機も維持します。全履歴JSONと設定JSONは別形式です。

## 権限

| 権限 | 用途 |
| --- | --- |
| https://vrchat.com/* | 既存のログイン状態でAPIのGET要求を行う |
| alarms | 休止可能なサービスワーカーから定期取得 |
| storage | 設定・次回時刻・待機期限の保存 |
| unlimitedStorage | 観測履歴の容量制限と自動破棄を抑制。保存期間による削除は別途実施 |
| background | ログオン後・ウィンドウを閉じた後のChrome動作 |
| script.google.com / script.googleusercontent.com（任意） | GASの同期設定を保存するときに追加で要求する送受信権限 |
| api.vrchat.cloud / files.vrchat.cloud（任意権限） | 画像キャッシュを有効にした場合の画像取得 |
| declarativeNetRequestWithHostAccess | **この拡張自身のVRChat APIへのGETだけ**に識別用User-Agentを設定（vrchat.com、および権限付与済みのapi.vrchat.cloud） |

User-Agentはブラウザ本来の識別子を維持し、その末尾に `VRCFriendsObserver/0.3.2 連絡先` を明示します。VRChatサイトや他の拡張からの要求は書き換えません。VRChatは非公式API利用をサポートしておらず、User-Agentへの付加形式も個別承認を受けたものではありません。観測APIが転送を返した場合は追従せず停止します。画像取得のみVRChatの画像配信先への転送に対応し、応答先と画像形式・サイズを検証します。

### GASの設定確認と接続診断

GASエディターの `createSyncToken` で同期キーを生成し、スクリプトプロパティから拡張へコピーします。有効な既存キーは維持されます。`setup` は不正な設定項目を日本語で表示します。コードを更新したら、公開範囲を「全員」にして新バージョンで再デプロイしてください。

拡張の「収集設定 → 接続状態・診断」で、保存済み設定、Googleへの権限、最終同期試行・エラー・待機期限を確認できます。「接続テスト」は保存済みのURLとキーでhelloだけを送信し、HTTPステータス・最終URL（クエリ除外）・応答コードを表示します。入力欄を変更した場合は先に保存してください。キーや応答本文を診断には残しません。

通常の自動再試行は指数バックオフを使います。「今すぐ同期」「接続テスト」は拡張側の待機を解除できますが、サーバー指定のRetry-Afterは期限まで維持します。この変更はGAS同期のみで、VRChat収集の待機規則は従来どおりです。
