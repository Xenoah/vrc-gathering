# Googleスプレッドシート同期の導入

このフォルダーの `Code.gs` と `Protocol.gs` をGoogle Apps Script（GAS）に配置します。拡張内の「収集設定」または「使い方」→「GASセットアップ手順を見る」でも同じ流れを確認でき、必要なコードをコピー・保存できます。既存のVRChat認証はそのままChromeで扱い、GASへは観測済みの記録だけを送ります。観測記録は同期を有効にしたときだけ送信します。「接続テスト」は同期が無効でも、保存済みキーを使ってhelloを送ります。

## 1. スプレッドシートとGASを作る

1. Googleスプレッドシートを新規作成します。共有設定は非公開のままにしてください。
2. URLの `/spreadsheets/d/` と次の `/` の間にあるスプレッドシートIDを控えます。
3. シートの「拡張機能 → Apps Script」を開きます。
4. `Code.gs` を同名ファイルに貼り付け、スクリプトファイル `Protocol` を追加して `Protocol.gs` の内容を貼り付けます。両方が必要です。
5. プロジェクトの設定 → スクリプトプロパティで `SPREADSHEET_ID` と必要なら `RETENTION_DAYS` を設定します。エディターで **`createSyncToken` を選んで実行**すると、64文字の `SYNC_TOKEN` が自動生成・保存されます。

| プロパティ | 値 |
| --- | --- |
| `SPREADSHEET_ID` | 手順2のID |
| `SYNC_TOKEN` | `createSyncToken` が生成・保存。実行後、スクリプトプロパティの値をコピーして拡張にも設定 |
| `RETENTION_DAYS` | クラウド保存日数。**0＝期限なし（未設定も同じ）**。1〜365で観測履歴を日次整理 |

`createSyncToken` は有効な既存キーを上書きしません。生成したキーは実行ログや戻り値には出さず、スクリプトプロパティで確認できます。手動で設定する場合は32〜256文字の英数字・ハイフン・アンダースコアが必要です。キーを作り直したら、拡張にも貼り付け直して保存してください。空欄で保存すると以前のキーを維持するため、新しいキーには置き換わりません。

同期キーはGASと拡張の両方へ同じ値を設定します。コード・Git・チャットへ書き込まず、スクリプトプロパティと拡張の設定画面で管理してください。このキーを知る人は、このGASに保存した全アカウントの記録を読み書きできます。個人用、または記録を共有してよい端末だけで使ってください。

6. `setup` 関数を選択して一度実行し、Google側のアクセス許可を確認します。`VRCFriends`・`VRCEvents`・`VRCWorlds`・`VRCRuns`・`VRCAccounts`・`VRCVisits`・`VRCEncounters`・`VRCProfiles`・`VRCXFollowers` と、下記の7種類、`VRCSchema`・`VRCArchives` および、保存期間を日次チェックするトリガーが作成されます。繰り返し実行しても同じトリガーは重複しません。

GASのV8ランタイムを使います。必要なら「appsscript.json マニフェスト ファイルをエディタで表示する」を有効にし、同梱の `appsscript.json` を参考に設定してください。

## 2. ウェブアプリを公開する

1. 「デプロイ → 新しいデプロイ → ウェブアプリ」を選びます。
2. 「次のユーザーとして実行」は **自分**、「アクセスできるユーザー」は **全員** にします。**「自分のみ」のままでは、拡張のPOSTがGoogleのログイン画面へ転送され、doPostも実行数も記録されません。** GAS自身がPOST本文の同期キーを照合します。スプレッドシートを公開する必要はありません。
3. デプロイして、末尾が `/exec` のURLをコピーします（`/dev` ではありません）。

Google Workspaceの組織設定で「全員」を選べない場合、この方式のGAS公開は利用できません。管理者が認める方法で公開できるアカウントが必要です。

コードを更新するときは、GASの「デプロイを管理 → 編集 → 新バージョン」で既存のデプロイを更新します。コード保存だけでは公開済みの内容は更新されません。

## 3. 拡張で同期する

1. 更新後の `extension` をChromeに読み込むか、`chrome://extensions` で再読み込みします。
2. ダッシュボードの「収集設定 → Googleスプレッドシート同期」を開きます。
3. GASのURLと同期キーを入力し、「記録をGoogleスプレッドシートと同期する」をオンにして保存します。
4. Googleのスクリプト用ドメインへの追加接続権限を許可します。既存のVRChat権限とは別です。
5. 「接続状態・診断」で `script.google.com` と `script.googleusercontent.com` が両方「許可済み」であることを確認します。未許可なら「Googleへの接続を許可」を押します。
6. **「接続テスト」→「今すぐ同期」** を実行します。接続テストはhelloだけを送り、HTTPステータス・最終URL（クエリ除外）・応答コードを表示します。通常の同期は既存ローカル記録を送信します。GASの「実行数」に `doPost`（種類：ウェブアプリ）が増え、`VRCFriends` などのシートに行が追加されることを確認してください。ローカル記録がまだない場合は、先にVRChatの収集を行う必要があります。
7. 別端末でも同じURLとキーを登録すると記録が受信され、アカウント選択に表示されます。閲覧専用の端末では収集開始やVRChatログインは不要です。

キー入力欄は保存後に空になります。保存済みの場合、空欄のまま保存すると元のキーを維持します。同期キーは端末内の `chrome.storage.local` に保存し、CSV・JSON・シートの観測データには含めません。

## 同期とデータの扱い

- ローカル保存を続けながら、収集完了後・画面表示／タブ切替時・約5分ごと・「今すぐ同期」で送受信します。通常の自動同期は60秒以上空けます。
- 画面は端末内のデータを先に表示し、受信完了後に更新します。ネットワークが切れても表示・収集・ローカル保存は継続します。
- 全アカウントのフレンド、変更履歴、ワールド情報、巡回記録、アカウント表示名を同期します。VRChatのCookie、パスワード、トークン、API連絡先、GASの同期キーは観測データに含めません。
- 初回は保存済み全件、以後は変更分を100件ずつ送信します。受信はサーバーの更新番号でページングします。1回の処理は送信・受信各最大10ページ、約2分を目安に区切り、残りは次回に続けます。
- 応答が失われても同じ記録の再送で重複しません。最新状態は観測日時が新しい方を優先し、同時刻は正規化JSONの辞書順で決定します。履歴の識別はアカウント・ユーザー・観測ミリ秒です。別端末が同じユーザーを同じミリ秒に異なる状態で観測した場合も、この優先規則で1件に統合します。
- エラー後は1分から最大1時間の待機を設け、HTTPのRetry-Afterが長い場合はそちらを守ります。「今すぐ同期」と「接続テスト」は拡張自身の待機を無視して再試行できます。サーバーの `Retry-After` は別の期限として保持し、手動操作や同じURLのキー変更・端末記録削除では短縮しません。旧版で記録したHTTPエラーの待機は、出所を区別できないため期限まで維持します。
- クラウドと端末の保存期間は別設定です。受信時も端末の保存期間を超える記録は取り込みません。GASは古い記録も受け付けます。RETENTION_DAYSが1〜365の場合は日次トリガーで履歴を整理します。期間指定読み込みは別の一時キャッシュへ保存するため、端末の通常保存期間より前の分析もできます。
- 主ファイルの作業用テーブルと各月別ファイルはそれぞれ最大50,000レコードです。過去月は自動整理し、容量が近づいた場合は終了済みの当月履歴も分割ファイルへ移します。GAS／Sheetsの実行時間・利用枠の制約もあるため、大規模な長期収集用途には別のバックエンドが必要です。

## v0.2.xからGASを更新する

1. 既存のスプレッドシートを必要に応じてバックアップし、`Code.gs` と `Protocol.gs` の両方を更新します。
2. 同じ `SPREADSHEET_ID`・`SYNC_TOKEN` で `setup` を実行します。旧 `VRCRecords` を種類別テーブルへコピーし、IDと更新番号を引き継ぎます。途中で時間切れになった場合は再実行できます。
3. 「デプロイを管理 → 編集 → 新バージョン」で既存のURLを更新します。拡張の「今すぐ同期」で確認します。
4. 旧 `VRCRecords` は移行元バックアップとして残り、以後の更新・日次整理の対象外になります。移行と同期を確認してから、不要なら旧シートを手動削除してください。`VRCSchema` の移行フラグは変更しません。

旧拡張も新GASへ接続できます。新拡張を旧GASへ接続した場合は「旧GAS互換モード」と表示します。v2の拡張項目保持を使うため、GASも更新してください。1つのシートは1つのGASプロジェクトから更新し、各端末は同じウェブアプリURLを使います。

## シートを見る・記録を削除する

種類別の18個の記録シートで表示名・状態・ワールドIDなどを確認できます。`observed_at_ms` は観測のUnixミリ秒、`received_at_ms` はGAS受信時刻、`payload_json` は復元に使うJSONです。式として扱われうる表示名は文字列として保存します。

`VRCSchema`、`VRCArchives`、ヘッダー、`record_id`、`revision`、`payload_json`、および `SEQ_<datasetId>` プロパティは編集・初期化しないでください。シート上の手編集を各端末に同期する機能はありません。画像と画像URLはローカルキャッシュ専用で、シートへ送信しません。

データ形式、レコードID、互換規則、将来の名前空間付き項目追加は [PROTOCOL.md](PROTOCOL.md) を参照してください。

拡張の「この端末の記録を削除」は **端末内のみ** を削除して収集・同期を停止します。クラウドに残ったデータは、同期を再開すると戻ります。端末の削除は他端末・クラウドへ伝播しません。

すべての記録を消すには、全端末で収集・同期を停止し、各端末の記録を削除してから 18種類の記録シートのヘッダーを残してデータ行を削除します。`VRCArchives` に記載した各月別ファイルの記録行も削除します。アーカイブファイルを削除する場合は対応するVRCArchivesの行も取り除きます。旧 `VRCRecords` が残っていればそのバックアップも削除します。`VRCSchema` と `SEQ_<datasetId>` は維持します。データが残った端末が同期すると再送されるため、全端末の削除を先に済ませてください。接続を取り消したい端末がある場合は、GASの `SYNC_TOKEN` を新しい値に変更し、利用を続ける端末だけに新キーを設定します。

## 確認・トラブルシューティング

| 状況・診断コード | 確認すること |
| --- | --- |
| 保存時の `ParseError: Unexpected token =` | v0.3.0のCode.gsにはGASエディター非対応の `||=` が含まれていました。最新版のCode.gsとProtocol.gsをコピーし直して保存します。 |
| `Error: CONFIG` / setupが失敗 | 最新版でsetupを実行すると `SPREADSHEET_ID` 未設定、`SYNC_TOKEN` の文字数・使用文字、`RETENTION_DAYS` の範囲を日本語で表示します。キーが短い／未設定ならcreateSyncTokenを実行してください。公開APIの応答は秘密値を含まないCONFIGのままです。 |
| `PUBLIC_ACCESS` / ログイン画面やHTMLが返る | 「デプロイを管理 → 編集」でアクセスできるユーザーを「全員」にし、「新バージョン」でデプロイします。URLも `/exec` か確認してください。 |
| `PERMISSION` | 2つのGoogleドメインの接続権限を許可します。権限がない場合、拡張はfetchを行いません。 |
| `SETTINGS` / 未保存 | URLとキーを先に保存します。接続テストは入力中の値ではなく保存済み設定を使います。 |
| `AUTH` | GASのスクリプトプロパティからSYNC_TOKENをコピーし直し、拡張の同期キー欄へ貼り付けて保存します。 |
| `NETWORK` / HTTP応答なし | 接続権限・ネット接続・URL・公開範囲を確認します。ブラウザが応答へのアクセスを拒否した場合もこの表示になり、GASへの到達は確認できません。 |
| `REQUEST` / 旧版 | 接続テストのhelloに未対応です。GASの両ファイルを更新して再デプロイします。 |
| `HTTP` / サーバー指定の待機 | 表示された期限まで待ちます。HTTPステータスやRetry-Afterは接続先が返した値です。 |
| 同期中のまま | 拡張を更新・再読み込みし、「同期の段階」と最終試行を確認します。同期完了を確認できないまま150秒、接続テストで30秒を過ぎた場合は再試行操作が有効になります。GASへ到達しているかは接続テストで確認してください。 |
| 自動再試行の待機 | 設定を直したら「接続テスト」や「今すぐ同期」で再試行できます。 |
| `LIMIT` | GASでpruneRecordsを実行し、必要なら保存期間を短縮します。 |

GASの実行数にdoPostがないときは、保存済み設定の有効／無効、両ドメインの権限、最終同期試行、最終同期エラー、次回再試行を順に確認してください。キー不一致のAUTH応答が返れば、GASまで到達したことは確認できます。ブラウザでURLを開いたときの `POST_REQUIRED` はGETに対する正常応答で、拡張のPOST到達を確認したことにはなりません。

診断画面や診断データには同期キー・応答本文を含めず、最終URLのクエリ・フラグメントも除外します。接続テスト成功後も、実際の記録送信は「今すぐ同期」で確認してください。GASのコードを保存しただけでは公開済みバージョンは更新されません。

ランキングからは古い観測を除外します。同期成功だけで観測日時は新しくならず、収集側のChromeが稼働している必要があります。

開発時は `npm ci --ignore-scripts` の後に `npm test` と `npm run check:gas` を実行します。GAS本体をSheetsモックで検証し、AcornのES2020パーサーと新しいランタイムメソッドの検査で構文互換性の回帰を防ぎます。`python3 tests/browser_smoke.py` は画面・IndexedDB、`python3 tests/sync_browser_smoke.py` は実同期クライアントとChrome／HTTPモックによる診断操作を検証します。これらは実GASエディターでの保存・公開先への到達確認の代替ではありません。


## v0.5.0の訪問・同席履歴を同期する

GASのCode.gsとProtocol.gsを最新版へ置き換え、既存のスクリプトプロパティを維持してsetupを実行し、新バージョンで再デプロイします。VRCVisits（自分の訪問区間）とVRCEncounters（同インスタンス／同ワールドの観測区間）が追加されます。

新しい拡張はhelloで対応する記録の種類を確認します。旧GASには従来の記録だけを送り、新しい履歴は端末内に保持して更新案内を表示します。更新後は読み取りカーソルを初期位置から確認し、新しい種類の過去の行も取り込みます。新GASを旧拡張が使う場合も、旧拡張には従来の種類だけを返します。従来のシート列・設定・データセットIDは維持します。

## 全収集データの同期へ更新する（v0.8.0）

1. 最新の **Code.gs・Protocol.gsの両方**を既存プロジェクトへ貼り付けます。
2. 全期間を残す場合はスクリプトプロパティ **RETENTION_DAYSを0** に変更します。既存のSPREADSHEET_ID・SYNC_TOKENはそのまま使います。
3. **setupを実行**し、VRCProfilesを含む18種類の記録シートを確認します。
4. **デプロイを管理 → 編集 → 新バージョン**で既存URLを更新します。
5. 拡張の「今すぐ同期」を実行します。「一部未同期」が解消し、確認済みのXリンクがあればVRCProfilesにデータが入ることを確認します。

新しい種類はhelloのkindsで通知します。更新前のGASには非対応データを送らず、更新後は既存の端末データを追加送信します。旧拡張は対応する種類だけを引き続き読み取れます。

収集データは18種類の表へ保存し、分析結果は元記録から再計算します。画像と画像URLは従来どおりローカルキャッシュにのみ保存します。Cookie・認証トークン・同期キー・収集設定は含みません。

pushは保存期間を過ぎた記録も保存し、受領件数だけ返して破棄することはありません。RETENTION_DAYSを1〜365に設定した場合は日次整理が観測履歴に適用されます。0なら全期間を保管します。Xリンクのスナップショットは履歴整理の対象外です。各ファイルは最大50,000行に区切ります。主ファイルに分割できない最新状態や未終了区間が50,000行ある場合はLIMITを返し、未送信分を完了扱いにしません。


## Xフォロワー数の同期へ更新する（v0.9.0）

Code.gsとProtocol.gsを両方置き換え、同じスプレッドシートID・同期キーでsetupを実行します。VRCXFollowersが追加されます。「デプロイを管理 → 編集 → 新バージョン」で更新してから、拡張で同期してください。保存期間0の設定は引き続き全期間保存です。

xFollowersは、Xプロフィールで確認した数値・URL・確認日時・概数の区別・取得元を保持します。最新値のスナップショットで、フォロワーの個別名簿や増減の時系列履歴ではありません。Xリンクの確認時刻とフォロワー数の確認時刻は独立します。旧GASで未対応の場合は未同期と表示し、更新後に送信します。


## v0.10.0：変化点・時系列・月別ファイル

既存URLとキーを維持し、Code.gs・Protocol.gsを更新してsetupを実行、再デプロイします。追加される表は以下の7つです。

| 表 | 内容 |
| --- | --- |
| VRCUserSegments | ユーザー状態の確認区間 |
| VRCWorldCrowd | 観測フレンド人数・インスタンス数・取得範囲 |
| VRCCoverage | 全件／部分取得・停止・エラー・確認区間 |
| VRCFollowerHistory | Xフォロワー数の変化と確認時刻 |
| VRCAnnotations | イベント・メモ・タグ |
| VRCViews | 保存した分析条件・レポート周期 |
| VRCReports | 生成したレポートと対象期間 |

同じ値は同じrecord_idへ上書きし、確認時刻はbase36差分列のchecksとして保存します。確認回数・最終確認・変化点を保持します。行を無限に伸ばさないため、UTCの月境界または最大1,024確認時刻で分割します。記録形式と巡回時刻の復元は [PROTOCOL.md](PROTOCOL.md) を参照してください。

setup／日次整理で、終了済みの過去月の履歴をGoogle Drive内の **VRC Gathering YYYY-MM archive N** ファイルに移します。VRCArchivesに年月・ファイルID・行数・更新番号の上限を保存します。ファイル名は変更できますが、ID・記録ID・更新番号・JSONは編集しないでください。Sheetsの作成には既存のスプレッドシート権限を使います。コピーと索引の保存後に元の行を除去し、中断時は再実行して復旧します。最新状態・Xリンク・保存条件・イベントは主ファイルに残ります。

拡張の「時系列・比較 → スプレッドシートから選択期間を読み込む」で過去の期間を取得します。一度に最大1,000件で区切り、続きがあれば同じボタンで継続します。通常同期のカーソルとは独立し、24時間の端末キャッシュから分析します。取得済みアーカイブは再送しません。選択期間を変えたら先頭から読み込みます。RETENTION_DAYSによって既に削除された記録は取得できません。

Googleの実行時間・ファイル数・容量の利用枠は引き続き適用されます。アーカイブを別所有者へ共有・移動する場合もGAS実行者のアクセス権を維持してください。


## 公式ユーザーノートの同期へ更新する（v0.13.0）

1. 同梱の **Code.gsとProtocol.gsを両方** 置き換えます。拡張の「収集設定 → GASセットアップ」からもコピー・保存できます。
2. 既存のスプレッドシートID・同期キーを維持して `setup` を実行します。`VRCUserNotes` と `VRCUserNoteHistory` が追加され、計18種類の記録表になります。
3. 「デプロイを管理 → 編集 → 新バージョン」で再デプロイします。
4. 拡張で「今すぐ同期」を実行します。旧GASで未同期だった公式ノートも送信します。

`VRCUserNotes` はアカウント・対象ユーザーごとの最新値、`VRCUserNoteHistory` は本文の変化を初めて確認した時点の記録です。本文は `note_text`、対象は `user_id`、公式ノートIDは `note_id`、公式の作成日時は `note_created_at_ms`、現在の本文を初めて記録した日時は `changed_at_ms`、最終確認は `observed_at_ms` です。個別プロフィールからはノートID・公式作成日時を取得できないため、未取得のときは空欄にします。日時はUnixミリ秒です。

本文は式として実行されない文字列で保存し、復元には `payload_json` を使います。シート上の手編集は拡張・公式サイトへ送信しません。最新値は期間削除・月別移動から除外します。変更履歴は既存の期間設定と月別整理に従い、RETENTION_DAYSが0なら全期間を保管します。空になったノートも最新値として残し、以前の記録を再送しても復活させません。
