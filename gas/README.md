# Googleスプレッドシート同期の導入

このフォルダーの `Code.gs` と `Protocol.gs` をGoogle Apps Script（GAS）に配置します。既存のVRChat認証はそのままChromeで扱い、GASへは観測済みの記録だけを送ります。同期を有効にするまでは外部送信しません。

## 1. スプレッドシートとGASを作る

1. Googleスプレッドシートを新規作成します。共有設定は非公開のままにしてください。
2. URLの `/spreadsheets/d/` と次の `/` の間にあるスプレッドシートIDを控えます。
3. シートの「拡張機能 → Apps Script」を開きます。
4. `Code.gs` を同名ファイルに貼り付け、スクリプトファイル `Protocol` を追加して `Protocol.gs` の内容を貼り付けます。両方が必要です。
5. プロジェクトの設定 → スクリプトプロパティに次を追加します。

| プロパティ | 値 |
| --- | --- |
| `SPREADSHEET_ID` | 手順2のID |
| `SYNC_TOKEN` | パスワードマネージャー等で生成した、ランダムな32〜256文字の英数字・ハイフン・アンダースコア |
| `RETENTION_DAYS` | クラウド保存日数。1〜365、未設定なら30 |

同期キーはGASと拡張の両方へ同じ値を設定します。コード・Git・チャットへ書き込まず、スクリプトプロパティと拡張の設定画面で管理してください。このキーを知る人は、このGASに保存した全アカウントの記録を読み書きできます。個人用、または記録を共有してよい端末だけで使ってください。

6. `setup` 関数を選択して一度実行し、Google側のアクセス許可を確認します。`VRCRecords` シートと、保存期間を日次チェックするトリガーが作成されます。繰り返し実行しても同じトリガーは重複しません。

GASのV8ランタイムを使います。必要なら「appsscript.json マニフェスト ファイルをエディタで表示する」を有効にし、同梱の `appsscript.json` を参考に設定してください。

## 2. ウェブアプリを公開する

1. 「デプロイ → 新しいデプロイ → ウェブアプリ」を選びます。
2. 「次のユーザーとして実行」は **自分**、「アクセスできるユーザー」は **全員** にします。GAS自身がPOST本文の同期キーを照合します。スプレッドシートを公開する必要はありません。
3. デプロイして、末尾が `/exec` のURLをコピーします（`/dev` ではありません）。

Google Workspaceの組織設定で「全員」を選べない場合、この方式のGAS公開は利用できません。管理者が認める方法で公開できるアカウントが必要です。

コードを更新するときは、GASの「デプロイを管理 → 編集 → 新バージョン」で既存のデプロイを更新します。コード保存だけでは公開済みの内容は更新されません。

## 3. 拡張で同期する

1. 更新後の `extension` をChromeに読み込むか、`chrome://extensions` で再読み込みします。
2. ダッシュボードの「収集設定 → Googleスプレッドシート同期」を開きます。
3. GASのURLと同期キーを入力し、「記録をGoogleスプレッドシートと同期する」をオンにして保存します。
4. Googleのスクリプト用ドメインへの追加接続権限を許可します。既存のVRChat権限とは別です。
5. 上部の表示が「同期完了」になること、シートに記録が追加されることを確認します。既存のローカル記録も初回同期で送信します。
6. 別端末でも同じURLとキーを登録すると記録が受信され、アカウント選択に表示されます。閲覧専用の端末では収集開始やVRChatログインは不要です。

キー入力欄は保存後に空になります。保存済みの場合、空欄のまま保存すると元のキーを維持します。同期キーは端末内の `chrome.storage.local` に保存し、CSV・JSON・シートの観測データには含めません。

## 同期とデータの扱い

- ローカル保存を続けながら、収集完了後・画面表示／タブ切替時・約5分ごと・「今すぐ同期」で送受信します。通常の自動同期は60秒以上空けます。
- 画面は端末内のデータを先に表示し、受信完了後に更新します。ネットワークが切れても表示・収集・ローカル保存は継続します。
- 全アカウントのフレンド、変更履歴、ワールド情報、巡回記録、アカウント表示名を同期します。VRChatのCookie、パスワード、トークン、API連絡先、GASの同期キーは観測データに含めません。
- 初回は保存済み全件、以後は変更分を100件ずつ送信します。受信はサーバーの更新番号でページングします。1回の処理は送信・受信各最大10ページ、約2分を目安に区切り、残りは次回に続けます。
- 応答が失われても同じ記録の再送で重複しません。最新状態は観測日時が新しい方を優先し、同時刻は正規化JSONの辞書順で決定します。履歴の識別はアカウント・ユーザー・観測ミリ秒です。別端末が同じユーザーを同じミリ秒に異なる状態で観測した場合も、この優先規則で1件に統合します。
- エラー後は1分から最大1時間の待機を設け、HTTPのRetry-Afterが長い場合はそちらを守ります。手動同期でもエラー後の待機は短縮しません。
- クラウドと端末の保存期間は別設定です。受信時も端末の保存期間を超える記録は取り込みません。GASは保存期間を過ぎた記録を受け付けず、日次トリガーで整理します。
- シートは最大50,000レコードです。GAS／Sheetsの実行時間・利用枠の制約もあるため、大規模な長期収集用途には別のバックエンドが必要です。

## シートを見る・記録を削除する

`VRCRecords` の行は `friends`（最新状態）、`events`（変更履歴）、`worlds`、`runs`（巡回記録）、`accounts` に分かれています。表示名・状態・ワールドID等の列を確認できます。`observedAt` はUnixミリ秒、`payload` は復元に使うJSONです。式として扱われうる表示名は文字列として保存します。

ヘッダー、key、version、payload、および `SYNC_SEQUENCE` プロパティは編集・初期化しないでください。シート上の手編集を各端末に同期する機能はありません。

拡張の「この端末の記録を削除」は **端末内のみ** を削除して収集・同期を停止します。クラウドに残ったデータは、同期を再開すると戻ります。端末の削除は他端末・クラウドへ伝播しません。

すべての記録を消すには、全端末で収集・同期を停止し、各端末の記録を削除してから `VRCRecords` のヘッダーを残してデータ行を削除します。`SYNC_SEQUENCE` は維持します。データが残った端末が同期すると再送されるため、全端末の削除を先に済ませてください。接続を取り消したい端末がある場合は、GASの `SYNC_TOKEN` を新しい値に変更し、利用を続ける端末だけに新キーを設定します。

## 確認・トラブルシューティング

- 「同期キーが一致しません」：スクリプトプロパティと拡張に同じキーを設定します。
- 「GASがJSONを返しません」：`/exec` のURL、公開範囲「全員」、最新バージョンのデプロイを確認します。URLをブラウザで開いたときの `POST_REQUIRED` は正常です。データはGETでは返しません。
- 「別の同期が実行中」／通信エラー：次回の再試行を待ちます。失敗した記録の再送は安全です。
- 「保存上限」：GASで `pruneRecords` を実行して保存期間外のデータを整理し、必要なら保存日数を短縮します。
- UIの古い観測はランキングから除外されます。同期に成功しても観測日時自体は新しくなりません。収集側のChromeが稼働している必要があります。

開発時は `npm test` がGAS本体をSheetsモックで実行し、認証・再送・競合・ページングを検証します。`python3 tests/browser_smoke.py` はPlaywrightとChromiumで画面・IndexedDBを検証します。実GAS公開先での動作は、自分のGoogleアカウントでデプロイ後に上記手順で確認してください。
