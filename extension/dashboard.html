    Xのフォロワー数

    有効にしてXプロフィールを開くと、画面上のフォロワー数を保存します。対象は「確認済みのXリンクのみ」または「開いたXプロフィール全員」から選べます。全員モードではVRChatとのリンク未確認でも保存し、確認済みリンクがある場合だけVRChatユーザーの情報に反映します。X APIは使いません。「全取得」は確認済みのXリンクを未取得・古い順に更新します。

    全員モードの記録は、選んだ保存先アカウントにまとめます。保存後に開くXプロフィールが対象です。すでに開いているページは再読み込みしてください。

    「フレンド全員」は、表示アカウントの最新フレンド名簿から公開Xリンクを確認して一括取得します。24時間以内のリンク確認結果は再利用します。Xリンクがない人は対象外です。VRChatに同じアカウントでログインし、連絡先を保存してください。人数が多いと時間がかかります。Chromeを閉じた間は止まり、起動後に残りを続けます。

    専用タブの同時取得数は1〜10件（初期値3件）に設定できます。減らした場合は取得中の処理が終わるのを待って新しい上限を適用します。次の追加取得まで15秒以上空けます。個別の読み込み失敗は未着手の対象を先に処理してから1回再試行し、未確認が続いても残りの対象を処理します。未取得を優先し、取得済みは古い順に更新します。完了したバックグラウンドの専用タブは閉じます。自分で開いたタブや閲覧中のタブは閉じません。ログインや制限が出たら停止するので、Xの表示を確認してから再開してください。省略された数値は「約」と表示し、取得日時を残します。フォロワー一覧・投稿本文・画像は収集しません。Google同期が有効ならフォロワー数も送受信します。

    はじめてのGASセットアップ

    スプレッドシートの作成から同期開始まで、次の6ステップで設定できます。GAS（Google Apps Script）は、ご自身のGoogleアカウントで動作します。

    1. スプレッドシートを新規作成

      Googleスプレッドシートを作成 ↗し、共有設定は非公開のままにします。URLの /spreadsheets/d/ と次の / の間がスプレッドシートIDです。

    2. Apps Scriptにコードを配置

      シートの「拡張機能 → Apps Script」を開き、Code.gs の内容を置き換えます。スクリプトファイル Protocol も追加し、Protocol.gs の内容を貼り付けます。2つとも必要です。

      Code.gs保存・送受信の処理ファイルを保存
      Protocol.gs記録形式の検証ファイルを保存

      コードは拡張に同梱しています。コピーできない場合は「ファイルを保存」で取得し、テキストエディターから貼り付けてください。

    3. プロパティを設定し、同期キーを生成

      Apps Scriptの「プロジェクトの設定 → スクリプトプロパティ」でIDと保存日数を設定します。エディターで createSyncToken を選んで実行すると、64文字の同期キーが自動生成・保存されます。

      SPREADSHEET_ID
      手順1で控えたスプレッドシートID。
      SYNC_TOKEN
      createSyncToken が自動保存します。実行後、スクリプトプロパティから値をコピーして拡張の同期キー欄に設定します。ログには値を出しません。有効な既存キーは上書きしません。手動設定は32〜256文字の英数字・ハイフン・アンダースコアです。
      RETENTION_DAYS
      クラウドの保存日数。全期間を保管するには 0 を設定します。未設定も期限なしです。1〜365の場合はその日数で観測履歴を整理します。端末側の保存日数とは独立しています。

      同期キーを知る人は保存した全アカウントの記録を読み書きできます。キーは他人に共有せず、VRChatのパスワードや認証トークンは入力しないでください。

    4. setupを一度実行

      エディター上部で setup 関数を選んで実行し、Googleのアクセス許可を確認します。VRCFriends・VRCEvents・VRCWorlds・VRCRuns・VRCAccounts・VRCVisits・VRCEncounters と、形式情報を持つ VRCSchema、日次整理トリガーを作成します。

    5. ウェブアプリとしてデプロイ

      「デプロイ → 新しいデプロイ → ウェブアプリ」で、「次のユーザーとして実行」は 自分、「アクセスできるユーザー」は 全員 を選びます。「自分のみ」のままだと拡張からの要求はログイン画面へ転送され、doPostは実行されません。GAS側で同期キーを照合するため、スプレッドシート自体の公開は不要です。

      デプロイ後、末尾が /exec のURLをコピーします。/dev は使いません。組織の設定で「全員」を選べない場合は、管理者が認める公開方法を確認してください。

    6. この拡張にURLと同期キーを登録

      同期設定にGASのURLと SYNC_TOKEN と同じキーを入力し、「記録をGoogleスプレッドシートと同期する」をオンにして保存します。Googleへの追加接続権限を許可します。「接続状態・診断」で両ドメインが許可済みであることを確認し、「接続テスト」→「今すぐ同期」を実行します。GASの「実行数」にウェブアプリの doPost が記録され、シートに行が追加されることを確認してください。

      別端末でも同じURLとキーを登録できます。閲覧だけならVRChatへのログインや収集開始は不要です。

    既存のGASから更新する場合

    Code.gsとProtocol.gsの両方を置き換え、同じスプレッドシートID・同期キーで setup を実行してから「デプロイを管理 → 編集 → 新バージョン」で公開します。VRCProfiles・VRCXFollowers を含む19種類の記録シートを作成します。全期間を残すにはスクリプトプロパティのRETENTION_DAYSを0に変更してください。v0.2.xの旧 VRCRecords は種類別シートへ自動移行し、端末の既存記録も引き継ぎます。旧シートはバックアップとして残り、自動整理の対象外です。移行と同期を確認後、不要なら旧シートを手動で削除してください。

    VRCArchives に記載した月別ファイルへ過去の履歴を整理します。「時系列・比較」で期間を指定して読み戻せます。PCログの同席記録は VRCInstanceEncounters に保存します。公式ユーザーノートは VRCUserNotes と VRCUserNoteHistory に保存します。同期にはv0.14.0以降の両ファイルを更新し、setup・新バージョンで再デプロイしてください。VRCSchema・VRCArchives と更新番号・JSON列は編集しないでください。新しい拡張は旧GASでも従来の記録を同期できます。未対応の訪問・同席・時系列・レポート・公式ユーザーノートなどは「一部未同期」と表示し、GAS更新後に送受信します。画像と画像URLは端末内のキャッシュにのみ保存し、同期しません。収集設定・認証情報・同期キーは収集記録に含めません。

    うまく同期できないとき・GASを更新するとき
    Error: CONFIG／setupが失敗します
    最新の2ファイルを貼り付け、エディターから setup を実行すると、不正なプロパティ名と条件を日本語で表示します。SYNC_TOKENが未設定・短い場合は createSyncToken を実行し、生成された値を拡張にも保存してください。
    GASの実行数にdoPostがありません
    「接続状態・診断」で権限、最終試行、待機期限を確認します。URL・キーを保存して「接続テスト」を実行してください。PUBLIC_ACCESSなら公開範囲を「全員」にして新バージョンで再デプロイします。NETWORKなら接続権限・ネット接続・URLを確認してください。ブラウザでURLを開くだけではdoGetになり、doPostの確認にはなりません。
    ParseErrorでコードを保存できません
    最新版のCode.gsとProtocol.gsをコピーし直してください。v0.3.0の論理代入演算子を削除し、GAS用の構文検査を追加しています。
    同期キーが一致しません
    GASの SYNC_TOKEN と、拡張に入力したキーを確認します。保存済みのキーは、入力欄を空欄のまま保存すると維持されます。
    GASがJSONを返しません
    URLが /exec であることと、公開範囲が「全員」であることを確認します。URLをブラウザで開いたときの POST_REQUIRED は正常です。
    コードを更新したのに反映されません
    Apps Scriptの「デプロイを管理 → 編集 → 新バージョン」で既存のデプロイを更新します。コードの保存だけでは公開済みの内容は更新されません。
    GASの実行設定を確認したい
    V8ランタイムを使います。必要なら「appsscript.json マニフェスト ファイルをエディタで表示する」を有効にし、同梱のappsscript.jsonを保存して参考にしてください。

    端末内の記録を削除してもシートの記録は残り、同期を再開すると戻ります。クラウドと端末の保存日数は別設定です。

    保存される情報

    フレンドID、表示名、接続状態、ステータス・メッセージ、プラットフォーム、公開されたワールドID・名前・インスタンスID・種類・地域、観測日時と変更履歴。自分の訪問履歴と、フレンドとの同インスタンス／同ワールドの観測区間も保存します。ワールドの作者名・定員もキャッシュします。

    PC内の拡張専用データベースに保存。同期を有効にした場合は指定のGoogleスプレッドシートにも保存します。VRChatの認証情報は同期しません。インスタンスIDに作成者ID等が含まれる場合があります。

    ユーザー詳細を開くと、必要に応じて公開プロフィールのX（Twitter）リンクを確認します。XのURL・確認日時・対象IDだけを端末にキャッシュします（最大500人・再確認間隔24時間）。本文は保存しません。Google同期が有効ならXリンクの確認結果も送受信します。設定バックアップには含めません。

    記録をすべて削除

    この端末の全アカウントの記録とXリンクのキャッシュを削除し、収集・同期を停止します。スプレッドシートの記録は残ります。同期を再開すると再取得されます。

    Windowsで継続して使う

    1. 同じChromeプロファイルでログイン

      vrchat.comのログインと2段階認証を完了。パスワード・認証トークンをこの拡張に入力する必要はありません。

    2. 連絡先を保存して収集を開始

      収集設定にAPI識別用の連絡先を入力。拡張のアイコンから、いつでもこの画面を開けます。

    3. Chromeのバックグラウンド実行を有効に

      Chrome「設定 → システム → Google Chromeを閉じた際にバックグラウンドアプリの処理を続行する」を有効にします。Windowsログオン時の起動は同梱のwindows/Install-Startup.ps1でも設定できます。

    4. 履歴は定期的にエクスポート

      拡張の削除・プロファイル消去で記録も消えます。JSONは全履歴の保存用、CSVは一覧・差分の分析用です。全履歴JSONの手動再インポートは未対応です。設定のJSONは「収集設定 → 設定のバックアップ」で書き出し・読み込みできます。GAS同期では別端末の記録を取り込めます。

    Googleスプレッドシートと同期する

    GASの作成・公開・接続設定を、拡張内のガイドで進められます。必要なコードも同梱しています。

    収集が止まる条件

    Chromeの完全終了、Windowsのサインアウト／スリープ、ネット切断、認証切れ、サイト権限の未許可。Windowsのログオン前には動きません。

    公開範囲をそのまま扱う

    APIが所在を非公開にしている場合は「非公開」。非公開の居場所の推測、本人がいない場所の調査は行いません。同席ログでは、自分のゲームに記録された参加者を非フレンドも含めて取り込めます。

    大量のフレンドがいる場合

    1巡回でオンライン最大2,000件、オフライン名簿最大500件を取得し、続きは次回へ。ワールド名は最大5件ずつ補完します。ページ取得中の状態変化で重複や抜けが生じる場合があり、IDで重複排除します。

    エラー時の動作

    401／403は停止。429／通信失敗は待機し、Retry-Afterと指数バックオフを適用。停止・再開やデータ削除をしても待機時間は解除しません。
