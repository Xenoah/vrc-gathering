# vrc-gathering

**VRC Friends Observer** — 自分に公開されているVRChatフレンドの状態とワールドを、PC内へ記録するChrome拡張。

[ダウンロード](https://github.com/Xenoah/vrc-gathering/releases/latest) · [詳しい導入・操作手順](README_ja.md) · [検証状況](VALIDATION.md)

## 機能

- フレンド一覧、接続状態、ステータスメッセージ、公開ワールド／インスタンスの取得。
- ユーザー詳細からX（Twitter）へ移動。公開プロフィールに記載されたURLを取得し、確認結果を端末にキャッシュ。
- 観測時刻付きの変更履歴、検索、状態別フィルター。
- 概要画面とユーザー別の活動タイムライン。観測点・推定区間・時間帯別の変更件数、状態とワールドの観測上の継続時間。
- 「分析ラボ」に31種類の分析。期間比較、曜日×時刻ヒートマップ、ワールドの伸び・再訪・移動経路、同席の変化、共通ワールドのネットワークと2ユーザー比較、記録の品質を確認。期間／ユーザー／ワールドで絞り込み、集計CSV・分析JSONに出力。
- 全ユーザーのワールド遷移ネットワーク。ドラッグ・ズーム・スクロール、期間／ユーザー絞り込み、経路ごとのユーザー・観測日時表示。
- 最新の滞在フレンド数で集計するワールドランキング。一覧・ランキング・ネットワークの並べ替え条件も選択可能。
- ユーザー／ワールドの画像を端末にキャッシュ（任意設定、32MiB・1,000件まで）。
- GAS経由のGoogleスプレッドシート双方向同期（任意設定）。v2プロトコルと種類別テーブル、旧シートの自動移行に対応。拡張内にセットアップガイド・コードのコピー／保存を用意。[導入手順](gas/README.md)
- 一覧・変更履歴のCSV出力、アカウントごとの全履歴JSON出力。
- 自分のワールド訪問履歴と、フレンドとのつながり分析。同インスタンスと同ワールドを区別し、回数・推定時間・共通ワールドを図と表で表示。
- 設定のJSON書き出し・読み込み。同期キーの同梱を選択でき、内容確認後に復元。
- 既定3分間隔、ローカル保存、保存期間の設定。同期有効時は指定のスプレッドシートにも保存。
- 取得間隔のランダム化、レート制御、429のRetry-Afterと指数バックオフ。
- Windowsログオン時のChrome起動用スクリプトを同梱。

## インストール

1. [Releases](https://github.com/Xenoah/vrc-gathering/releases) の `vrc-gathering-v0.6.1.zip` をダウンロードし、固定フォルダーへ展開します。
2. Chromeの `chrome://extensions` で「デベロッパーモード」を有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」から、展開先の **`extension`** フォルダーを選びます。
4. 同じChromeプロファイルで [vrchat.com](https://vrchat.com/home) にログインします。
5. 拡張の「収集設定」にAPI識別用の連絡先を保存し、「収集を開始」を押します。

利用時のコンパイル・npmインストールは不要です。公式サイトのログイン状態をブラウザ経由で利用します。Windowsログオン後、対象のChromeプロファイルが動作している間に収集します。ウィンドウを閉じた後も使う場合は、Chromeのバックグラウンド実行を有効にしてください。

## 取得範囲と制約

取得するのは自分のアカウントから見える情報です。所在非公開はそのまま記録します。定期観測なので、取得間隔の間やPCスリープ中の移動は復元できません。記録はChromeプロファイル内に保存され、拡張・プロファイルの削除で失われるため、必要な履歴はエクスポートしてください。

v0.6.1は個人用の非公式ツールです。**121件のNode.jsテスト・GAS構文検査・配布ZIP生成、Chromiumでの画面・IndexedDB検証に合格しています。WindowsのChrome拡張としての実機動作、実際のVRChatログイン、および公開済みGASへの接続は未検証です。** 検証記録は [VALIDATION.md](VALIDATION.md) に記載しています。

## 開発・配布

利用時の追加依存はありません。開発テストにはNode.js 20以降、ZIP作成にはPython 3を使います。

```sh
npm ci --ignore-scripts
npm test
npm run check:gas
python scripts/package_release.py
```

配布物は `dist/` に作成します。GitHub Actionsはmain／PRでテストし、`v*` タグが付いたコードのバージョン一致を検証して、テストに合格したZIPとSHA-256をリリースへ公開します。

## Googleスプレッドシート連携

[gas/README.md](gas/README.md) に新規作成・GAS公開・同期設定の手順をまとめています。GASのURLと同期キーを拡張に保存すると、収集後・画面表示時・定期実行で変更分を送受信します。通信失敗時もローカル記録を使えます。

ランキングは選択中アカウントの新しい観測だけを集計し、所在非公開や古い観測を除外します。遷移図の矢印は観測順であり、正確な移動時刻を表しません。

開発用の実ブラウザチェックは `python3 tests/browser_smoke.py`（Python Playwrightと `/usr/bin/chromium` が必要）です。同期プロトコルを変更したら `python3 scripts/sync_gas_protocol.py` でGAS側の共通コードも更新してください。

GASセットアップは拡張の「収集設定」または「使い方」から開けます。拡張フォルダーだけでも必要なGASコードを取得できます。アイコンは16／32／48／128pxを同梱し、ツールバー・拡張一覧・ダッシュボードで共通のデザインを使用します。開発時の再生成は `bash scripts/build_icons.sh`（ImageMagickが必要）です。

GASの初期設定は `createSyncToken` でキーを生成し、`setup` で設定を検証できます。拡張の「接続状態・診断」には権限・試行／エラー・待機期限と接続テストを用意しています。通常の再試行待ちは手動操作で解除できますが、サーバーのRetry-Afterは維持します。診断UIのブラウザ検証は `python3 tests/sync_browser_smoke.py` です。

「収集設定 → 設定のバックアップ」で保存済み設定を書き出し・読み込みできます。同期キーは既定で含めず、チェックした場合だけ暗号化せずに保存します。読み込み時は収集を停止し、Google同期・画像取得に必要な接続権限を確認します。設定バックアップのブラウザ検証は `python3 tests/settings_browser_smoke.py` です。

自分・つながり機能の履歴をSheetsへ同期するには、GASの `Code.gs`・`Protocol.gs` を更新し、`setup` を実行して新バージョンで再デプロイしてください。旧GASでも従来の記録は同期し、訪問・同席履歴は更新まで端末内に保存します。操作検証は `python3 tests/connections_browser_smoke.py` で実行できます。

v0.6.0の分析ラボは保存済み記録を端末内で集計します。v0.5.0用GASからの追加更新は不要です。分析の一覧・指標の意味は [README_ja.md](README_ja.md#分析ラボ31種類の分析) を参照してください。操作検証は `python3 tests/analysis_lab_browser_smoke.py` です。
