# vrc-gathering

**VRC Friends Observer** — 自分に公開されているVRChatフレンドの状態とワールドを、PC内へ記録するChrome拡張。

[ダウンロード](https://github.com/Xenoah/vrc-gathering/releases/latest) · [詳しい導入・操作手順](README_ja.md) · [検証状況](VALIDATION.md)

## v0.17.0：フレンド全員のXフォロワー数を一括取得

「収集設定 → Xのフォロワー数 → 全取得の対象」で **フレンド全員（Xリンクも確認）** を選んで保存し、**全取得** を押してください。最新のフレンド名簿から公開Xリンクを確認し、フォロワー数が未取得 → 古い順に別タブで取得します。24時間以内のリンク確認結果は再利用します。

リンクあり・なし・取得失敗を分けて表示し、停止・再開やChrome再起動でも残りを引き継ぎます。Xリンクが公開されていない人は数値取得の対象外です。従来の確認済みリンクのみの方式、同時取得数1〜10件、設定と記録を維持します。GAS更新は不要です。[操作方法](README_ja.md#フレンド全員のxフォロワー数を取得するv0170)

## v0.16.0：開いたXプロフィール全員を保存するモード

「収集設定 → Xのフォロワー数 → 開いたXの対象」で **開いたXプロフィール全員** を選び、保存先アカウントを指定して保存してください。VRChatのリンク未確認でも、開いたXプロフィールのフォロワー数・確認日時を保存します。「保存したXプロフィール」で検索・並べ替えできます。

従来の「確認済みのXリンクのみ」も選べ、旧設定はそのまま引き継ぎます。VRChatユーザーへの対応付けには確認済みリンクを使います。「全取得」の対象は別の設定で選べます。設定バックアップ・既存のGoogle同期に対応し、この変更のためのGAS更新は不要です。

## v0.15.0：自分の現在地・参加者を確認して記録

「全ユーザー同席」の **現在地・参加者を取得して記録** で、ログイン中の自分のワールド・インスタンスと、APIが返す参加者（非フレンドを含む）を取得します。通常の収集を停止していても1回取得でき、現在地・確認日時・参加者一覧・フレンド関係・今回の区間の観測開始を表示します。自動取得は従来どおり「収集を開始」で動きます。

自分の訪問履歴と相手ごとの同席区間を保存し、同じ状態は既存区間を更新します。参加者一覧を取得できない場合も現在地を記録し、未取得と0人を区別します。Google同期が有効なら既存の訪問・同席テーブルへ同期します。v0.14.0以降のGASからの更新は不要です。[操作方法](README_ja.md#自分の現在地参加者を取得して記録v0150)

## v0.14.1：Xの全取得が途中停止する問題を修正

個別の読み込み失敗が3件続くと、未処理が残ったまま停止する処理を修正しました。未取得を優先し、読み込み失敗は1回再試行してから未確認として残し、残りの対象を処理します。ログイン要求・利用制限では理由を表示して停止します。

「収集設定 → Xのフォロワー数 → 同時取得数」で **1〜10件（初期値3件）** を選んで保存できます。設定バックアップにも含まれます。更新前に停止していた取得は「再開」で続けられます。この修正に伴うGAS更新は不要です。

## v0.14.0：非フレンドを含む同席履歴

「全ユーザー同席」で、In InstanceのAPIが返す参加者とPC版VRChatの参加・退出ログから、相手ごとの同席回数・合計時間・最初と最後の同席・ワールド別の区間を集計できます。現在のフレンド／非フレンド、期間、記録元で絞り込み、並べ替え・CSV出力に対応します。

Windows補助スクリプトとフォルダー監視を設定すると、ダッシュボードを開いている間に更新します。同じログは同じ区間を更新し、重複コピーは集計時に時間を二重加算しません。終了がない区間は最終ログまでとし、「終了未確認」を表示します。

Questで遊んでいる場合も、Chromeで収集が動き、APIが現在地と参加者一覧を返す範囲で記録します。全員の一覧が常に返ることは保証できません。**PCを停止している間はこの拡張も収集しません。** APIの同席時間は定期観測からの推定区間として、PCログの時刻と区別します。

Sheets保存には **GASのCode.gs・Protocol.gsを更新 → setup → 再デプロイ** してください。新しい表は `VRCInstanceEncounters` です。画像はローカルのまま、ログ本文・会話・参加用nonceは送信しません。[PCログの設定・集計方法](README_ja.md#pcログから全ユーザーの同席を記録v0140)

## v0.13.1：Xフォロワー取得の重複を修正・3件並行取得

一括取得の途中で同じプロフィールが再登録される問題と、ユーザー詳細の更新が未取得より先に処理される問題を修正しました。未取得 → 確認日時の古い順で選び、最大3アカウントを同時に取得します。旧版の取得待ち・設定・記録を引き継ぎます。この修正に伴うGAS更新は不要です。

## v0.13.0：VRChat公式ユーザーノートを記録

VRChat公式プロフィールのノートを取得して、ユーザー詳細に表示します。定期収集でノート一覧を取り込み、詳細を開いたときや「公式ノートを再取得」でも確認できます。編集は「VRChatで編集」から公式サイトで行います。

最新値は同じ行を更新し、本文が変わったときだけ変更履歴を追加します。取得失敗や一覧からの欠落で本文を消さず、公式プロフィールで空欄を確認できた場合にクリアを記録します。アカウント別に保存し、記録JSONとSheets同期にも含めます。

同期には **GASのCode.gs・Protocol.gsを更新 → setup → 新バージョンで再デプロイ** が必要です。`VRCUserNotes` と `VRCUserNoteHistory` が追加されます。[操作手順](README_ja.md#公式ユーザーノートの記録v0130) · [GAS更新手順](gas/README.md#公式ユーザーノートの同期へ更新するv0130)

## v0.12.0：ワールド遷移を円形・2D・3Dで探索

「探索・遷移図」で、従来の円形に加え、2D／3D表示を選べます。X・Y・Zに滞在人数、移動回数、流入／流出、接続先、最終観測、定員、制作者など13種類の指標を自由に割り当て、等間隔／対数の目盛りで比較できます。3Dは回転・平行移動・ズーム、右ドラッグ＋WASD／QE移動、Fキーで選択地点へのフォーカスに対応します。

点の人気サイズ、経路の色と光の流れ、ローカル画像を維持します。表示と軸の設定をブラウザーに保存し、通常のデータ更新では視点を維持します。GASの更新は不要です。詳しい操作は [README_ja.md](README_ja.md#ワールド遷移ネットワークの2d3d表示v0120) を参照してください。

## v0.11.0：Xフォロワー数を別タブで取得

一覧または設定の「全取得」で、確認済みのXリンクを **未取得 → 確認日時が古い順** に取得します。専用タブを設定した数（1〜10件、初期値3件）まで同時に開き、プロフィールに表示された数値を読みます。X APIは使いません。取得を有効にした状態でユーザー詳細を開くと、そのユーザーを更新対象に追加します。一括取得中は未取得を優先します。直近1分の確認は再利用し、「フォロワー数を更新」ボタンでは再取得できます。

進捗・停止・再開に対応し、ワーカーが休止してもキューを保持します。ログイン・利用制限では停止し、以前の数値を維持します。対象はこのアカウントのフレンドについて確認済みのXリンクです。未確認のリンクを推測したり、X APIで検索したりしません。詳しくは [README_ja.md](README_ja.md#xフォロワー数の一括取得v0110) を参照してください。

## v0.10.0：時系列・比較と記録の圧縮

「時系列・比較」に8つのツールを追加しました。混雑・急上昇、全ユーザーの同席ネットワーク、観測品質、時刻再生、Xフォロワー数の増減、イベント前後比較、ワールドの特徴、保存条件・日次／週次レポートを利用できます。操作は [RESEARCH.md](RESEARCH.md) を参照してください。

状態が同じ間は同じ行の最終確認時刻と確認回数を更新し、確認時刻を差分形式で保存します。状態変化・欠測・月境界・レコード長の上限で区間を分けます。巡回記録も圧縮し、従来の分析では各巡回を復元します。既存の履歴・設定は残し、新しい時系列は更新後から蓄積します。

**GASのCode.gs・Protocol.gsを更新 → setup → 新バージョンで再デプロイ**してください。19種類の記録を同期し、過去月を月別スプレッドシートへ整理します。画像と画像URLは端末内のみです。

## 機能

- 黒・チャコールとシアンの分析ダッシュボード。推移・状態内訳・ワールド順位・同席相手をグラフで確認し、日付／ワールド／ユーザーから詳細分析へ移動。

- フレンド一覧、接続状態、ステータスメッセージ、公開ワールド／インスタンスの取得。
- ユーザー詳細からX（Twitter）へ移動。公開プロフィールに記載されたURLを取得し、確認結果を端末にキャッシュ。
- 観測時刻付きの変更履歴、検索、状態別フィルター。
- 概要画面とユーザー別の活動タイムライン。観測点・推定区間・時間帯別の変更件数、状態とワールドの観測上の継続時間。
- 「分析ラボ」に31種類の分析。期間比較、曜日×時刻ヒートマップ、ワールドの伸び・再訪・移動経路、同席の変化、共通ワールドのネットワークと2ユーザー比較、記録の品質を確認。期間／ユーザー／ワールドで絞り込み、集計CSV・分析JSONに出力。
- 全ユーザーのワールド遷移ネットワーク。ドラッグ・ズーム・スクロール、期間／ユーザー絞り込み、経路ごとのユーザー・観測日時表示。
- 最新の滞在フレンド数で集計するワールドランキング。一覧・ランキング・ネットワークの並べ替え条件も選択可能。
- ユーザー／ワールドの画像を端末にキャッシュ（任意設定、32MiB・1,000件まで）。
- GAS経由のGoogleスプレッドシート双方向同期（任意設定）。v2プロトコルと種類別テーブル、旧シートの自動移行に対応。拡張内にセットアップガイド・コードのコピー／保存を用意。[導入手順](gas/README.md)
- 一覧・変更履歴のCSV出力、アカウントごとの全履歴JSON出力。
- 自分のワールド訪問履歴と、フレンドとのつながり分析。同インスタンスと同ワールドを区別し、回数・推定時間・共通ワールドを図と表で表示。
- 設定のJSON書き出し・読み込み。同期キーの同梱を選択でき、内容確認後に復元。
- 既定3分間隔、ローカル保存、保存期間の設定。同期有効時は指定のスプレッドシートにも保存。
- 取得間隔のランダム化、レート制御、429のRetry-Afterと指数バックオフ。
- Windowsログオン時のChrome起動用スクリプトを同梱。

## インストール

1. [Releases](https://github.com/Xenoah/vrc-gathering/releases) の `vrc-gathering-v0.9.0.zip` をダウンロードし、固定フォルダーへ展開します。
2. Chromeの `chrome://extensions` で「デベロッパーモード」を有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」から、展開先の **`extension`** フォルダーを選びます。
4. 同じChromeプロファイルで [vrchat.com](https://vrchat.com/home) にログインします。
5. 拡張の「収集設定」にAPI識別用の連絡先を保存し、「収集を開始」を押します。

利用時のコンパイル・npmインストールは不要です。公式サイトのログイン状態をブラウザ経由で利用します。Windowsログオン後、対象のChromeプロファイルが動作している間に収集します。ウィンドウを閉じた後も使う場合は、Chromeのバックグラウンド実行を有効にしてください。

## 取得範囲と制約

取得するのは自分のアカウントから見える情報です。所在非公開はそのまま記録します。定期観測なので、取得間隔の間やPCスリープ中の移動は復元できません。記録はChromeプロファイル内に保存され、拡張・プロファイルの削除で失われるため、必要な履歴はエクスポートしてください。

v0.9.0は個人用の非公式ツールです。**136件のNode.jsテスト・GAS構文検査・配布ZIP生成、Chromiumでの画面・IndexedDB検証に合格しています。WindowsのChrome拡張としての実機動作、実際のVRChatログイン、および公開済みGASへの接続は未検証です。** 検証記録は [VALIDATION.md](VALIDATION.md) に記載しています。

## 開発・配布

利用時の追加依存はありません。開発テストにはNode.js 20以降、ZIP作成にはPython 3を使います。

```sh
npm ci --ignore-scripts
npm test
npm run check:gas
python scripts/package_release.py
```

配布物は `dist/` に作成します。GitHub Actionsはmain／PRでテストし、`v*` タグが付いたコードのバージョン一致を検証して、テストに合格したZIPとSHA-256をリリースへ公開します。

## Googleスプレッドシート連携

[gas/README.md](gas/README.md) に新規作成・GAS公開・同期設定の手順をまとめています。GASのURLと同期キーを拡張に保存すると、収集後・画面表示時・定期実行で変更分を送受信します。通信失敗時もローカル記録を使えます。

ランキングは選択中アカウントの新しい観測だけを集計し、所在非公開や古い観測を除外します。遷移図の矢印は観測順であり、正確な移動時刻を表しません。

開発用の実ブラウザチェックは `python3 tests/browser_smoke.py`（Python Playwrightと `/usr/bin/chromium` が必要）です。同期プロトコルを変更したら `python3 scripts/sync_gas_protocol.py` でGAS側の共通コードも更新してください。

GASセットアップは拡張の「収集設定」または「使い方」から開けます。拡張フォルダーだけでも必要なGASコードを取得できます。アイコンは16／32／48／128pxを同梱し、ツールバー・拡張一覧・ダッシュボードで共通のデザインを使用します。開発時の再生成は `bash scripts/build_icons.sh`（ImageMagickが必要）です。

GASの初期設定は `createSyncToken` でキーを生成し、`setup` で設定を検証できます。拡張の「接続状態・診断」には権限・試行／エラー・待機期限と接続テストを用意しています。通常の再試行待ちは手動操作で解除できますが、サーバーのRetry-Afterは維持します。診断UIのブラウザ検証は `python3 tests/sync_browser_smoke.py` です。

「収集設定 → 設定のバックアップ」で保存済み設定を書き出し・読み込みできます。同期キーは既定で含めず、チェックした場合だけ暗号化せずに保存します。読み込み時は収集を停止し、Google同期・画像取得に必要な接続権限を確認します。設定バックアップのブラウザ検証は `python3 tests/settings_browser_smoke.py` です。

自分・つながり機能の履歴をSheetsへ同期するには、GASの `Code.gs`・`Protocol.gs` を更新し、`setup` を実行して新バージョンで再デプロイしてください。旧GASでも従来の記録は同期し、訪問・同席履歴は更新まで端末内に保存します。操作検証は `python3 tests/connections_browser_smoke.py` で実行できます。

v0.6.0の分析ラボは保存済み記録を端末内で集計します。v0.5.0用GASからの追加更新は不要です。分析の一覧・指標の意味は [README_ja.md](README_ja.md#分析ラボ31種類の分析) を参照してください。操作検証は `python3 tests/analysis_lab_browser_smoke.py` です。

UIの可視化・キーボード操作・390〜1600pxのレイアウト検証は `python3 tests/dashboard_ui_browser_smoke.py` です。v0.7.0では31分析の集計内容・GAS・記録形式・設定の保存先を維持し、グラフと折りたたみ式データ表を追加しました。

Xリンク・フォロワー数を含む19種類の記録を同期します。画像と画像URLは従来どおりローカルキャッシュにのみ保存します。通常ホイール・光点停止は `python3 tests/network_browser_smoke.py` で検証できます。

ステータス色、フォロワー数の更新・並べ替えとXヘッダーの解析は `python3 tests/x_profile_browser_smoke.py` で検証できます。Xの画面はテスト用のHTMLで再現しています。

一括取得の別タブ・優先順位・自動／手動更新・制限時の停止は `python3 tests/x_collection_browser_smoke.py` で確認できます。Xのページ応答とChrome API境界をテスト用に置き換え、実際のChromiumタブ・ワーカー・DOM解析を使います。

全フレンドのリンク確認・設定・停止再開・進捗表示は `python3 tests/x_friend_discovery_browser_smoke.py` で確認できます。VRChat APIとChrome境界を架空データで再現し、実アカウントには接続しません。
